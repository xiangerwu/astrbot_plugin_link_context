# 使用方式與讀取限制

[返回首頁](https://github.com/xiangerwu/astrbot_plugin_link_context/blob/main/README.md) · [English overview](https://github.com/xiangerwu/astrbot_plugin_link_context/blob/main/README.en.md)

## 平台支援

| 來源 | 讀取方式 | 限制 |
| --- | --- | --- |
| 圖片直接網址 | JPG／PNG／WebP／GIF，包含 Discord 附件圖片連結；GIF 最多抽取 8 幀 | 需有圖片副檔名；保留簽名查詢參數，但已過期連結無法下載 |
| PTT | HTML 主文、推文、作者、內嵌及文字／超連結中的圖片 | 已刪文、連線限制仍會失敗；外連圖片可能無法下載 |
| Twitter / X | FxEmbed 公開貼文 API，正文、引用文字、配圖 | 連結 ID 會送到第三方；不支援私密／需登入內容 |
| Threads | Chromium 載入後核對貼文 shortcode 的結構化資料 | 沒有正文時只取核對過網址的公開預覽，明確標示缺漏；預覽不提供配圖 |
| Bilibili | 影片資訊 API、動態／Opus 圖文 API，支援短網址 | 僅影片標題、簡介、封面；風控可能回傳 412，Cookie 也不保證成功 |
| 其他網頁 | HTML article／main／body 文字與圖片 | 不保證動態、登入、付費牆內容；不解析 PDF／檔案下載 |

這不是「所有網址都能完整閱讀」的保證。失敗、處理中、截斷與未理解的圖片都會留在記錄裡，讓聊天模型知道哪些內容不能聲稱看過。

GIF 會依幀編號均勻取樣，包含第一幀與最後一幀，最多 8 幀按順序合併成一次圖片模型請求。這比單張圖片增加圖片輸入用量；抽幀可能漏掉短暫動作，不能據此判斷動作速度。其他動圖格式目前仍只讀第一幀。這適用於直接圖片網址及網頁配圖，不會下載影片。

## 讀取開關與回覆機率

「是否讀取連結」由 AstrBot 的插件啟用與會話插件設定控制；「是否自然接話」沿用 AstrBot 的群聊主動回覆機率。兩者獨立：沒有觸發聊天的連結仍會排入背景閱讀，讀取成功也不會自動發送回覆。

在 AstrBot WebUI 選擇該 Discord Bot／會話使用的配置，搜尋「主動回覆」（介面可能顯示簡體「主动回复」）：

| 設定 | 用途 |
| --- | --- |
| `provider_ltm_settings.active_reply.enable` | 啟用群聊自然接話；停用不會關閉本插件的背景讀取。 |
| `provider_ltm_settings.active_reply.method` | 選擇 `possibility_reply`，沿用官方機率判定。 |
| `provider_ltm_settings.active_reply.possibility_reply` | `0.0` 到 `1.0`，例如 `0.05` 為每次符合條件時約 5% 的機率。 |
| `provider_ltm_settings.active_reply.whitelist` | 限制哪些會話可主動接話；不是連結閱讀白名單，也不同於全域存取控制白名單。 |

5% 是每次獨立抽樣，不保證每 20 則剛好回 1 則，也不限於連結訊息。@ Bot／喚醒條件走正常聊天流程，不受這個隨機主動回覆機率控制。其他主動聊天插件另有自己的觸發設定；本插件不修改它們。

依 [AstrBot 4.29.4 的實作](https://github.com/AstrBotDevs/AstrBot/blob/v4.29.4/astrbot/builtin_stars/astrbot/group_chat_context.py)，本插件不新增另一套機率、不設定喚醒旗標，也不為了避免回覆而停止訊息事件。全域存取控制白名單若先擋下頻道／討論串，插件就不會收到訊息，連結也不會讀取。

從 0.1.1 起，讀取事件會先於內建群聊處理器排隊，讓當輪聊天至少能看到「正在讀取」。如果模型開始回覆時圖片仍未完成，當輪只提供實際已取得的狀態；完成後不補發，下一輪聊天才能取得完成的結果。

## 分享與查詢

1. 群組貼一個連結，插件排入背景工作，不發消息。
2. 背景讀取完成後，在同一會話問「剛剛那篇在講什麼」或自然討論；由目前人格與聊天模型回答。
3. 太早詢問時模型只會取得「正在讀取」記錄。完成後不會自動補發回覆，需下一次聊天才會注入新內容。

閱讀記錄依 AstrBot 的 `unified_msg_origin` 隔離。若 AstrBot 設為群組內按使用者分開會話，就會跟著分開，其他人的會話不會自動共享記錄。只辨識訊息文字裡完整的 HTTP(S) 網址；QQ 分享卡片、圖片中的網址與單獨 BV 號不在第一版範圍。

每輪暫時注入最多 18,000 字元，單筆先放 6,000 字元；模型可以透過 `link_context_read` 工具分頁讀取已保存的記錄。網頁正文最多保留 24,000 字元，圖片理解後的總記錄有大小限制，所有截斷都會標記。這是近期記憶，沒有永久知識庫。

資料寫入 AstrBot 管理的 `data/plugin_data/astrbot_plugin_link_context/links.sqlite3`。圖片工作檔完成後移除。預設單一背景工作、最多排隊 32 個連結；滿載、整筆失敗或重載中斷後可重貼以重試。同一會話內仍在處理或已完成的相同網址會略過，不會重複付費讀圖。`ready` 只代表流程完成，仍可能包含圖片失敗、公開預覽或截斷；這類記錄在保留期限內重貼也不會重讀，重載插件不會清除已完成記錄。

本插件不會改動其他插件。若原本的連結解析插件仍在轉發，需要在它自己的設定停用自動轉發或停用該插件。AstrBot 本身原有的聊天觸發規則也仍然有效。
