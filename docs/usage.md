# 使用方式與讀取限制

[返回首頁](https://github.com/xiangerwu/astrbot_plugin_link_context/blob/main/README.md) · [English overview](https://github.com/xiangerwu/astrbot_plugin_link_context/blob/main/README.en.md)

## 平台支援

| 來源 | 讀取方式 | 限制 |
| --- | --- | --- |
| 圖片直接網址 | JPG／PNG／WebP／GIF，包含 Discord 附件圖片連結；GIF 最多抽取 8 幀 | 需有圖片副檔名；保留簽名查詢參數，但已過期連結無法下載 |
| PTT | HTML 主文、推文、作者、內嵌及文字／超連結中的圖片 | 已刪文、連線限制仍會失敗；外連圖片可能無法下載 |
| Twitter / X | FxEmbed，失敗時改用 VXTwitter；核對貼文 ID | 第三方公開貼文、引用與圖片；不支援私密貼文 |
| Threads | 先解析分享轉址，讀取目標貼文靜態 JSON 或核對網址的公開預覽；不足才啟動 Chromium | 有 JSON 時保留正文與配圖；只有預覽時不把頭像當配圖，文字可能截斷 |
| Bilibili | 官方影片／動態 API；失敗時讀取 vxbilibili 公開預覽，支援可轉址的短網址 | 預覽可能截斷；影片仍只有標題、簡介、封面 |
| Instagram | oginstagram，失敗時 vxinstagram 預覽；貼文、Reels、限時動態網址 | 取決於服務是否仍能取得公開內容；不是完整相簿，過期限動／私密內容不可保證 |
| Facebook | facebed 公開預覽，含分享網址與 Reels | 不登入 Facebook；預覽可能截斷或失效 |
| TikTok | 短網址轉址後讀 tnktok／tiktokez 預覽 | 僅文字與預覽圖，未觀看影片 |
| Bluesky | 核對 DID 與貼文 URI 的官方 API，失敗時 bskx JSON | 公開文字、配圖與影片存在標記；不讀整串回覆 |
| Misskey.io | notes/show API，核對 note ID | 目前僅 misskey.io；正文、CW、引用文字與圖片，不支援其他實例 |
| 巴哈姆特 | 場外／論壇及小屋頁面 Open Graph 預覽 | 不新增帳密登入；需要年齡、手機驗證或會員登入的內容會失敗 |
| Plurk | 公開貼文的文字區塊與圖片 | 不登入、不讀整串回應 |
| Pixiv | 作品 AJAX API，失敗時 phixiv 預覽 | 作品說明與第一張預覽；不下載多頁全集或動畫 |
| Steam Workshop | 公開作品詳情 API | 說明與預覽圖；不下載模組／遊戲檔案 |
| PChome 24h | 商品與描述 JSONP API | 商品名稱、簡介、讀取時價格與圖片，價格／庫存可能變動 |
| E-Hentai／ExHentai | E-Hentai 公開圖庫 API，核對 gallery ID | 僅圖庫標題、標籤與封面，不登入 ExHentai、不閱讀整本 |
| nhentai | 圖庫 API，核對 ID／第一頁路徑 | 標題、標籤、頁數與第一頁，不閱讀整本 |
| 其他網頁 | HTML article／main／body；無正文時嘗試公開 metadata 預覽 | 不保證動態、登入、付費牆內容；不解析 PDF／檔案下載 |

0.2.0 的新增平台使用獨立資料讀取，不需要安裝 ermiana，也不會等待或讀取它在 Discord 的回覆。X／Bilibili 的主來源和預覽備援每次限時 5 秒；新增平台讀取合計最多 12 秒（不包含後續圖片模型）。Threads 原站快速讀取最多 5 秒，未取得可核對文字時仍可能進入較慢的瀏覽器流程。

這不是「所有網址都能完整閱讀」的保證。失敗、處理中、截斷與未理解的圖片都會留在記錄裡，讓聊天模型知道哪些內容不能聲稱看過。

GIF 會依幀編號均勻取樣，包含第一幀與最後一幀，最多 8 幀按順序合併成一次圖片模型請求。這比單張圖片增加圖片輸入用量；抽幀可能漏掉短暫動作，不能據此判斷動作速度。其他動圖格式目前仍只讀第一幀。這適用於直接圖片網址及網頁配圖，不會下載影片。

## 讀取開關與回覆機率

「是否讀取連結」由 AstrBot 的插件啟用與會話插件設定控制；「是否自然接話」沿用 AstrBot 的群聊主動回覆機率。兩者獨立：沒有觸發聊天的連結仍會排入背景閱讀，讀取成功也不會自動發送回覆。

在 AstrBot WebUI 選擇該 Discord Bot／會話使用的配置，搜尋「主動回覆」（介面可能顯示簡體「主动回复」）：

| 設定 | 用途 |
| --- | --- |
| `provider_ltm_settings.active_reply.enable` | 啟用群聊自然接話；停用不會關閉本插件的背景讀取。 |
| `provider_ltm_settings.active_reply.method` | 選擇 `possibility_reply`，沿用官方機率判定。 |
| `provider_ltm_settings.active_reply.possibility_reply` | `0.0` 到 `1.0`，例如 `0.05` 為每次符合條件時約 5% 的機率。 |
| `provider_ltm_settings.active_reply.whitelist` | 限制哪些會話可主動接話；不是連結閱讀白名單，也不同於全域存取控制白名單。 |

5% 是每次獨立抽樣，不保證每 20 則剛好回 1 則，也不限於連結訊息。@ Bot／喚醒條件走正常聊天流程，不受這個隨機主動回覆機率控制。其他主動聊天插件另有自己的觸發設定；本插件不修改它們。

依 [AstrBot 4.29.4 的實作](https://github.com/AstrBotDevs/AstrBot/blob/v4.29.4/astrbot/builtin_stars/astrbot/group_chat_context.py)，本插件不新增另一套機率、不設定喚醒旗標，一般分享連結也不會停止訊息事件。手動重讀指令會停止後續事件，避免同一指令再觸發一般讀取或聊天。全域存取控制白名單若先擋下頻道／討論串，插件就不會收到訊息，連結也不會讀取。

讀取事件會先於內建群聊處理器排隊，讓當輪聊天至少能看到「正在讀取」。從 0.1.5 起，同一則訊息直接 @ Bot 並附上完整連結時，會在當輪回答前最多等待 15 秒，再注入最新結果；多個連結共用這 15 秒，只檢查本則訊息、目前會話的網址，不等待其他工作。一般貼連結、@ 其他人或只有喚醒文字不等待。

超時仍只提供「正在讀取」狀態，背景工作繼續；提示會要求模型不要承諾「讀完再回」。完成後不補發，可稍後在同一聊天再次詢問。這 15 秒不包含後續聊天模型生成與平台送出時間。

## 分享與查詢

1. 群組貼一個連結，插件排入背景工作，不發消息。
2. 背景讀取完成後，在同一會話問「剛剛那篇在講什麼」或自然討論；由目前人格與聊天模型回答。
3. 要當輪等結果，直接 @ Bot 並再次附上完整網址，例如 `@Bot 看看 https://example.com/post`。最多等 15 秒；超時或沒有附網址時，可能仍取得「正在讀取」記錄，完成後不會自動補發回覆。

閱讀記錄依 AstrBot 的 `unified_msg_origin` 隔離。若 AstrBot 設為群組內按使用者分開會話，就會跟著分開，其他人的會話不會自動共享記錄。只辨識訊息文字裡完整的 HTTP(S) 網址；QQ 分享卡片、圖片中的網址與單獨 BV 號不在第一版範圍。

每輪暫時注入最多 18,000 字元，單筆先放 6,000 字元；模型可以透過 `link_context_read` 工具分頁讀取已保存的記錄。網頁正文最多保留 24,000 字元，圖片理解後的總記錄有大小限制，所有截斷都會標記。這是近期記憶，沒有永久知識庫。

資料寫入 AstrBot 管理的 `data/plugin_data/astrbot_plugin_link_context/links.sqlite3`。圖片工作檔完成後移除。預設單一背景工作、最多排隊 32 個連結；滿載、整筆失敗或重載中斷後可重貼以重試。同一會話內仍在處理或已完成的相同網址會略過，不會重複付費讀圖。`ready` 只代表流程完成，仍可能包含圖片失敗、公開預覽或截斷；這類記錄在保留期限內重貼也不會重讀，可改用下方指令。重載插件不會清除已完成記錄。

## 手動重新讀取

從 0.1.4 起，在原本分享連結的群組／Discord 頻道或討論串輸入：

```text
/link_reread https://example.com/image.gif
```

這是 AstrBot 文字指令，不是 Discord 原生斜線指令。若你的喚醒前綴不是 `/`，請使用已設定的前綴，或 @ Bot 後輸入 `link_reread 完整網址`。Discord 簽名連結須保留 `?` 後的完整參數。

- 只重讀目前會話已有的相同網址，包含最近 20 筆以外但尚存在的記錄；其他頻道的記錄不能借此讀取。沒有記錄時請先直接分享連結。
- 已完成、失敗或中斷的記錄會立即重新排隊，無需等待保留期限；舊 GIF 會按目前的最多 8 幀流程重新分析。圖片會再次產生模型費用。
- 正在排隊／處理中的連結不重複排入。佇列滿或資料庫無法寫入時不取代舊記錄。
- 排入後以「重新讀取中」取代舊內容，完成後保存新結果；來源失效或重新讀取失敗時會記錄失敗，不會繼續把舊結果當作新結果。
- 指令只回覆一次排隊或失敗狀態，不轉發內容、不自動補發完成通知。稍後在同一聊天詢問內容即可。

這個指令不能讓已過期的 Discord 附件網址重新有效；需要重新取得有效連結並分享。

本插件不會改動其他插件。若原本的連結解析插件仍在轉發，需要在它自己的設定停用自動轉發或停用該插件。AstrBot 本身原有的聊天觸發規則也仍然有效。
